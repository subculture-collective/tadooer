# Tadooer design system

Status: adopted 2026-09-23 for the web app; identity section added 2026-10-02;
workspace shell, task row and add bar rules added 2026-11-03 (issue #194).
`apps/web/src/tokens.css` is the source of truth for values;
`tokens.css` beside this file imports those custom properties, and
`examples/01-specimen.html` shows them without the app. The Studio brand pack
in `subcult-tv/studio/brands/tadooer/` copies this directory
with hashes and holds the promotional artwork; promotional layouts are edited
there, interface rules here.

## Identity

**Name.** Tadooer, written with one capital in prose and in the wordmark. The
repository is `subculture-collective/tadooer`; the workspace package and
container image names stay `productivity-suite`, and the build
and readiness endpoints report `service: "productivity-suite"`; the desktop and
mobile shells check that value, so it is an identifier, not a name.

**What it is.** A private, self-hosted task and calendar planner for one owner,
with a web app, desktop and mobile shells around the same server, live sync
between open devices, and an assistant surface behind explicit approval.

**Mark.** Three list lines with a check in a purple disc, from
`apps/web/public/suite-icon.svg`: the list is the plan, the disc is the one
thing being done now. The lines are `--subtext` on `--crust`, the disc is
`--purple`, the check is `--crust`. The mark stays legible at 32 pixels because
every shape is solid; monochrome variants draw the disc as a ring. Keep a
quarter of the mark's height clear on all sides.

**Web assets.** `apps/web/public/favicon.svg`, `apple-touch-icon.png`,
`icon-512.png`, `icon-maskable-512.png` and `og.png` are generated by the
Studio pack from the mark and these tokens; `brand-assets.json` beside this
file records their source and hashes. Regenerate in Studio and copy; do not
edit the copies. `suite-icon.svg` stays as the mark's editable source.

**Wordmark.** "Tadooer" in Inter at weight 650 with tracking -0.015em, the same
setting as page titles. Lowercase is for identifiers only.

**Signed-out screens.** Sign-in and first-run setup show the mark with the
wordmark, the line "The plan, and the one thing now.", two sentences saying
what Tadooer is and that the instance is private and self-hosted, and, from
60rem, the Studio pack's planner day (`apps/web/src/auth-brand.tsx`). The mark
there has the pack's `--line-strong` border because it sits on `--crust`. The
planner day's row titles are placeholders, so it is hidden from assistive
technology. Below 60rem the form follows the copy directly.

**Voice.** The planner itself, quietly. The rules and sample copy are in
[Voice](#voice) below.

## Voice

The planner speaks for itself, in short present-tense sentences with one idea
each. Someone looks at this screen all day, so most of it says very little.

- Labels, buttons and menu items are one or two plain words: "Sync now",
  "Start focus", "Add task". They carry no voice.
- The voice shows in page descriptions, empty states, the focus session,
  setup, reminders and errors.
- State what the software does and does not do. The product's own documents
  never claim a feature that is not verified.
- No exclamation marks. No praise when a task is completed. No talk of
  getting more done, streaks as a goal, or hustle.
- Tadooer is a private tool for one owner. Copy never invites anyone to sign
  up, never shows a server address as if it were public, and never describes
  a hosted service.
- An error says what happened, what happened to the owner's data, and what to
  do next. Sync, calendar and offline messages name the side that changed and
  say whether anything was written.
- Use "device" for a browser, desktop or phone the owner signed in on, and
  "the server" for the one Tadooer instance. Keep storage and protocol terms
  (cache, projection, canonical, CalDAV) out of interface copy unless the
  owner has to act on them.

Sample copy, as the app ships it:

| Where                        | Copy                                                                                                                          |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Today, before the plan loads | Here is the day.                                                                                                              |
| Today, nothing planned       | Today is clear.                                                                                                               |
| Inbox, empty                 | The inbox is empty. New tasks wait here until you give them a time.                                                           |
| Focus, no open task          | Focus needs an open task. Add one or reopen one.                                                                              |

## Direction

The default dark theme uses surfaces and text from Catppuccin Mocha.
The light option uses Latte surfaces. Accents come from
Dracula. The two palettes share a purple-leaning base, so the mix reads as one
system rather than a theme swap.

## Surfaces

Every layer has a job. Borders sit one step above the surface they sit on.
Depth comes from tint, not shadow; the only shadow is the overlay shadow on
dialogs and the auth card.

| Token                      | Value                 | Used for                                           |
| -------------------------- | --------------------- | -------------------------------------------------- |
| `--crust`                  | `#11111b`             | Outer frame, auth background, browser theme colour |
| `--mantle`                 | `#181825`             | Sidebar, inputs, nested form panels                |
| `--base`                   | `#1e1e2e`             | Page background                                    |
| `--surface-0`              | `#252538`             | Cards, task rows, popovers, dialogs                |
| `--surface-1`              | `#313244`             | Hover, selection, secondary buttons, chips         |
| `--surface-2`              | `#45475a`             | Pressed states, secondary button hover             |
| `--line` / `--line-strong` | `#2e2e44` / `#3a3a54` | Borders on surface-0 / inputs and controls         |

Text is `--text #e2e6f6`, nudged brighter than Mocha's default so body copy
still wins against saturated chips. `--subtext #a6adc8` is secondary copy,
`--subtext-2 #7f849c` is metadata and eyebrows.

## Accents, one meaning each

| Token      | Value     | Meaning                                                                            |
| ---------- | --------- | ---------------------------------------------------------------------------------- |
| `--purple` | `#bd93f9` | Primary action, selection, time blocks, focus session frame                        |
| `--pink`   | `#ff79c6` | Now. The current-time line, the live timer, the running focus label. Nothing else. |
| `--cyan`   | `#8be9fd` | Keyboard focus ring, links, informational chips, work calendars                    |
| `--teal`   | `#94e2d5` | Calendar authority: Baikal-owned calendars, planned-time metadata                  |
| `--green`  | `#50fa7b` | Success, sync online, working state, current freshness                             |
| `--orange` | `#ffb86c` | Warning, conflict, overdue, stale freshness, offline                               |
| `--red`    | `#ff5555` | Danger, destructive actions, errors, unavailable                                   |
| `--yellow` | `#f1fa8c` | Unassigned. Stays out of the UI until something earns it.                          |

Tinted fills (`--*-tint`) are the accent at 13 to 14 percent over transparent.
Use them for chips, banners, and highlighted rows. Never fill a large area with
a full-strength accent. Measured on `--base`: text 13.2:1, subtext 7.4:1, subtext-2 4.4:1,
purple 6.8:1, pink 6.9:1, cyan 11.8:1, teal 11.0:1, green 12.0:1,
orange 9.6:1, red 5.2:1. Crust on purple (primary button text) is 7.8:1.
Subtext-2 is below the 4.5:1 target for ordinary text, so it is limited to
eyebrows and metadata at weight 600.

Calm Day states map to chips: working is green, scheduled break is cyan,
unavailable is neutral, finished is purple. Live sync status uses the same
roles: live is green, reconnecting is orange, paused is neutral.

## Type

Inter Variable for text, Atkinson Hyperlegible Mono Variable for anything that
is a time, a revision, a token, or a count. Both are self-hosted through
Fontsource and imported in `main.tsx`. Mono always uses tabular numerals.

| Step          | Size | Use                                        |
| ------------- | ---- | ------------------------------------------ |
| `--text-2xs`  | 11px | Eyebrows, chips, uppercase field labels    |
| `--text-xs`   | 12px | Hints, metadata                            |
| `--text-sm`   | 13px | Controls, secondary copy, buttons          |
| `--text-base` | 14px | Body, task titles                          |
| `--text-lg`   | 16px | Section headings                           |
| `--text-xl`   | 20px | Auth headings                              |
| `--text-2xl`  | 24px | Page titles, weight 650, tracking -0.015em |

## Shape and density

Default controls are 36px tall. Task rows have a 52px minimum height.
Radius is 4px on controls and task rows, 8px on nested panels, 12px on cards. Under
a coarse pointer, controls grow to a 44px minimum and form text to 16px (the
touch block at the end of the stylesheet, issue #117).

## Motion

Motion is restrained: it confirms that something happened and nothing more.
Three durations: `--motion-fast` (120ms) for hover, `--motion-base` (180ms)
for rows and dialogs, and `--motion-panel` (240ms) for disclosures, sheets and
route transitions. `--ease-out` handles state changes; `--ease-enter` handles
entries and panel movement.
Task rows, board items, history entries and opened `details` content use the
`enter-fade` keyframe (opacity and a 2px rise). Dialogs use the shadcn
fade and zoom. The `prefers-reduced-motion: reduce` rule in section 4 of the
stylesheet shortens every animation and transition to effectively zero, so
nothing here needs its own override.

Loading uses `LoadingList` from `components/ui`: placeholder rows that hold
the layout until data arrives, with a visually hidden label as a polite
status region. Show it only while a request is in flight and the list is
empty; an empty result keeps `EmptyState`, and an offline page shows its
cached or empty state rather than a placeholder that never resolves.

## Component rules

- The frame (issue #194) is a desktop layout: a 16.25rem sidebar on `--mantle`
  that collapses to a 3.5rem icon rail (remembered per browser under
  `tadooer.sidebar:collapsed`), a 4rem header spanning the main and
  detail columns, the main column at 65rem, and a 23rem detail column on
  `--surface-0` that exists only while one task is selected. Below 64rem the
  sidebar moves into a modal drawer above bottom navigation, and the detail
  panel is a bottom `Sheet`. The
  components are `WorkspaceShell`, `Sidebar`, `Header`, `FocusStrip`,
  `SyncIndicator` and `TaskDetailPanel` under `components/shell`.
- The sidebar lists Today, Inbox, Planner, Tasks, Boards and Habits, then
  Projects and Tags as navigable contexts (`/projects/<id>`, `/tags/<id>`;
  the Tasks list with that filter fixed and its dropdown hidden), then
  Records and Setup (issue #175). Today and Inbox carry open-task counts;
  every project and tag shows its swatch and count. Groups remember their
  state under `tadooer.sidebar-group:<id>` and open while they hold the
  current location. The command bar lists the same contexts.
- The header holds the view title, the focus strip (title, countdown in
  `--pink` with a 1.5px underline while running, pause, break and complete;
  "No session" otherwise; a follower sees Take over), one sync dot coloured
  by the worst of task sync, live updates and Baikal with the three states
  as text in a status region and in a popover, a conflict badge only when
  conflicts need action, the command bar trigger and the account menu.
- Task rows (`TaskRow`) have a 3.25rem minimum height: a square complete toggle,
  the title, metadata in mono (`Overdue` or planned time, estimate as
  `45m`, `due Fri` within a week), the project chip with its swatch, up to
  three tag chips with `+n`, and actions that appear on hover, focus or
  selection: Start focus (a `Running` badge when the task owns the session),
  Schedule (a popover with the time block form, only while calendar actions
  are available), day-order arrows where a saved order exists, and a menu
  with Edit title, Add child task, Save as template, Archive and Delete.
  Clicking the body selects (`--primary-tint` fill, 2px `--purple` bar,
  `aria-selected`, roving tab stop); Shift extends and Ctrl toggles; two or
  more selected rows replace the add bar with the bulk bar (Complete,
  Archive, Delete, Move to project), which runs the per-task writes in order
  and names the first failure. Double-click, Enter or the menu edit the title
  in place; Escape restores it. Children nest one level under a chevron;
  a child whose parent is filtered out renders at top level without indent.
- The add bar (`AddTaskBar`) is one input pinned to the top of Today, Inbox,
  Tasks and the context routes, with More for notes, estimate, new-tag
  consent and the markers switch. Markers are on by default while online
  (issue #184) and remembered under `tadooer.capture:markers`; offline, the
  bar says "Offline: plain capture". "Paste a list" opens a dialog; the
  captured-links preference lives in Settings.
- The detail panel shows the selected task: an in-place title, Start focus,
  then Plan (planned day and time, time block, estimate and deadline),
  Organize (project, tags, placement), Notes (rendered, with an edit
  toggle), Child tasks, Checklist, Links and Recurrence (the last two need a
  session token), and a footer with Save as template, Archive and Delete.
  Escape or the close button clears the selection.
- Keyboard: ArrowUp and ArrowDown move the selection through the visible
  order, Enter edits the title, D completes, Y toggles focus, S opens the
  schedule in the panel, Shift+N adds a child, O opens details, Delete
  deletes, Escape clears, Shift+A focuses the add bar. Every binding is
  owner-editable in Settings; unmodified keys stay inert in inputs.
- The shell header's `h1` is the only page title (issue #196). A view opens
  with `ViewIntro`: a one-line description and its actions, no heading.
- Views group content in `ViewSection` (`ViewSectionHeader`,
  `ViewSectionBody`): a `section` on `--base` with a `SectionHeading` `h2` and
  a bottom `--line`, not a bordered card. Rows and panels inside keep
  `--surface-0`. `Card` stays for contained objects, not page sections.
- A task title shown outside the task lists (Planner day order, the
  unplanned drawer, board panels) is a `TaskTitleButton` that opens the task
  in the detail panel. On Planner, a task entry or a calendar block linked to
  a task opens the panel; a plain event opens the Planner's details sheet.
- Use `SectionHeading` and `EmptyState` inside sections; controls use the
  primitives in `components/ui`.
- Use `Button` variants for primary, secondary, ghost, and destructive actions.
  Set `type="button"` for actions inside a form that do not submit it.
- `NativeSelect` preserves native form submission. Named `Checkbox` controls
  inside forms retain their hidden native input for `FormData`.
- Associate each `FieldLabel` with a unique control ID.
- Use `Alert` for feedback and `Badge` for compact state labels. Preserve
  explicit status and alert roles where they convey asynchronous updates.
- The Tasks page has two sections selected by tabs in the page header and
  kept in the URL (issue #171): **Tasks** (`/tasks`) holds the add bar, the
  filter bar, saved views, sections and the list, with recently deleted
  tasks behind a disclosure; **Organize** (`/tasks/organize`) holds project
  and tag creation, lifecycle and appearance, sidebar folders and recurring
  series. Configuration never shares a scroll with the list. Settings stays
  for owner preferences and connections, not for records. The route audit
  and screenshots are in [information-architecture.md](information-architecture.md).
- A board's Gitea project (issue #174, ADR 0054) lives in a disclosure under
  the board's header, closed until a mapping exists. Sync results list moved
  tasks and conflicts in plain sentences; a conflict is never auto-resolved.
- Drag-and-drop (issue #172) uses the native HTML drag API with a private
  data type, no library: the unplanned-tasks drawer's rows are draggable,
  planner days and board panels are drop targets with a dashed purple
  outline while hovered. Every drop has an equivalent control: the drawer's
  select-and-place form, the day-order arrows on Today rows and the board
  Move button, so nothing depends on a pointer. A drop on a board runs the same
  previewed move as the button. dnd-kit was considered and left out until a
  reorder-by-drag need appears; the native API covers placement.
- The Planner uses a day, three-day, or week time grid with separate all-day
  rows and overlap lanes. Each day follows the selected timezone, including
  DST. Tasks without estimates show an explicit 30-minute placeholder.

## Cascade layers

Everything after the token blocks in the stylesheet lives in `@layer base`
(reset, typography, native form controls) or `@layer components` (every
class-based rule). Tailwind's utilities layer is declared after both. Keep new
rules inside one of those two layers. The one exception is the touch block in
`@layer utilities`, inside `@media (pointer: coarse)`, because the primitives
set their size with utilities.

## Phone layout

The viewport is `viewport-fit=cover` with `interactive-widget=resizes-content`.
The shell, the top bar, the auth card, dialogs and sheets pad with
`env(safe-area-inset-*, 0px)`. Full-height layout uses `100dvh`, never `100vh`.
At 48rem and below, long titles wrap and the page padding drops to 0.75rem.
`apps/web/src/phone-layout.test.ts` holds these rules in place.

## shadcn primitives

The primitives in `components/ui` consume the same tokens. There are no
`dark:` variants; the app is dark by default through `:root`. Badge gains
`success`, `warning`, `info`, `now`, and `calendar` variants that follow the
accent table above.

## Out of scope for now

Additional theme packs and wallpaper controls are outside this change.
The app already supports dark, light and system preferences. The Studio pack's
light and monochrome logo variants serve print and foreign backgrounds.
